## 1 双独立实现并存（架构）

```
                    ┌─ mine       src/western/natal.mjs   astronomy-engine 血统  porphyry/equal/whole  ← 主后端 (R-W12)
Sample_Input ──► 双盘 ┤
                    └─ kerykeion  py/kerykeion_chart.py   libephemeris 血统      Placidus              ← 并行校验
                                     ↓ 统一 schema
                          Part5 / Part6 / Part8 · 样本库
```

- 两个后端输出**同一 schema**（`{planets, aspects, angles, cusps, meta}`），下游只认这一个形状；
- `computeChart(backend, input)` 单后端；`computeDual(input)` 双盘 + 一致性核验；
- 一致性阈值（R-W11）：星体黄经最大 Δ ≤ **0.05°**、上升/天顶 Δ ≤ **0.15°**、kerykeion 硬相位覆盖率 ≥ **80%**、10 行星星座逐一致。
  未通过则**不静默入库**——`--add` 直接以 exit 4 退出并打印未通过明细。
- **kerykeion 缺失时优雅降级**：仍采集单盘，`charts.kerykeionError` 记录原因，`consistencyOk = null`（不是 false）。

## 2 Sample_Input 样板

```json
{
  "name": "匿名或代号", "gender": "男/女",
  "birth_date": {
    "calendar": "公历", "date": "2007-12-25", "time": "17:30", "time_precision": "精确到分",
    "birth_place": { "city": "成都", "province": "四川", "longitude": 104.06, "latitude": 30.67, "timezone": "Asia/Shanghai" }
  },
  "life_events": [ { "year": 2022, "event": "父亲生病", "category": "家庭/健康" } ]
}
```

| 字段 | 处理 |
|---|---|
| `calendar` | **只支持公历**；填「农历」→ **明确报错拒绝**（本引擎不做未经验证的历法换算，R-S3） |
| `time_precision` | 「大概到时辰」→ 通过但**告警**：四轴与宫位对时间极敏感，该样本不宜用于宫位类结论 |
| `gender` | 非必填但**强烈建议**（大运顺逆会反）；缺则告警并按男计 |
| `timezone` | 必填 IANA 名 → 走 **R-W8 历史时区**（含夏令时）换算 |
| `life_events` | **训练标签**：采集时自动算出该年流年干支、是否引动原局刑冲、是否冲夫妻宫、所在大运、流年干十神 |
| `life_events[].category` | **受控枚举**（R-S6）：`家庭/健康/学业/事业/婚恋/子女/财运/官非/迁移/人际/意外/其他`。复合写法（"家庭/健康"）由 `normalizeCategory` 拆成 主类别+`tags`；全不可识别 → **报错** |

### 类别枚举（R-S6）

```
家庭 健康 学业 事业 婚恋 子女 财运 官非 迁移 人际 意外 其他
```

- **为什么强制枚举**：自由文本跨样本聚合会散（首版库里出现了"家庭/健康"与"学业/事业"两个复合值），
  统计一散，"哪条规则在多少样本上复现"就无从谈起。
- **兼容旧写法**：按 `/ 、 , · + &` 与空白切分，取第一个可识别值为主类别，其余进 `tags`，**不丢信息**；
  同时含可识别与不可识别值 → 通过但告警；完全不可识别 → 报错并列出合法值。

## 3 每次采集写入本地库

| 产物 | 内容 |
|---|---|
| `data/samples.jsonl` | **只追加**事件流：每次采集一行完整记录（`kind:'sample'`），`:--verify` 另追加 `kind:'verification'` |
| `data/samples/<S-id>.json` | 单样本快照，便于人工翻阅 |

记录内容：`intake`（原始填写）+ `bazi`（四柱/强弱/用忌神/胎命身/格局/夫妻宫）+ `charts.mine` + `charts.kerykeion` +
`consistency`（逐体 Δ、四轴 Δ、相位覆盖）+ `events`（对齐后的标签）。

回放规则：**同 `id` 只保留最新一次采集**，历史行仍在文件里可追溯（与 `kb.jsonl` / `mapping-library.jsonl` 同一套设计）。

## 3.5 与 rules 库打通（每次采集自动记证据）

**规则规格**（`src/cross/event-rules.mjs`，7 条）：

| 族 | 含义 | 规则 |
|---|---|---|
| **A**（单样本可判） | 若事件年满足前提 P，则事件里应出现类别 C | A1 冲夫妻宫→婚恋｜A2 冲/害→健康·家庭｜A3 合→事业·学业｜A4 刑→官非·意外 |
| **B**（跨样本比较） | 特征 F 为真的样本，类别占比应高于其他样本 | B1 金星陷落→婚恋·财运｜B2 火星陷落→意外·健康｜B3 土星陷落→事业·官非 |

**打通方式（复用既有证据链，不新建库）**：每采一个样本，A 族结论经 `observe()` 写成 `rules` 证据：

```
from = "规则:A2"   to = "健康/家庭类事件"   chartId = 样本 ID   supports = true/false
```

于是 **6.7 的门槛自动适用于样本**：≥3 个**不同样本**且 0 反例 → `verified`；出现反例 → `contradicted`。
B 族**不在单样本下结论**（状态 `pending-ensemble`），只记录该样本的特征与占比，由集合比较给判定；
样本 <2 时明确报「样本不足」。

**视图**：`node cli-sample.mjs --rules`
→ 一张表回答「哪条规则在多少样本上复现、支持/反例各几、在 rules 库里是什么状态」。

## 4 实现裁定

| 编号 | 未定义处 | 裁定 |
|---|---|---|
| **R-W12** | 哪个后端为主 | **`mine` 为主**，kerykeion 为并行校验后端。理由：主后端必须无外部运行时依赖（Python venv）；kerykeion 作为独立实现的价值在"对拍"，不在"替换" |
| R-S1 | 样本 ID | `S-` + `sha1(日期 时刻\|经度,纬度\|精度)` 前 10 位内容哈希 → 同一人重复提交不会产生两条；改动时刻即换 ID |
| R-S2 | 一致性未通过怎么办 | **不静默入库**：CLI 以 exit 4 退出并打印未通过明细；库内记录仍含 `consistencyOk:false` 供排查 |
| R-S3 | 农历输入 | **明确拒绝**（`errors` 里给理由），不猜历法。要支持需另接经过验证的农历转换库 |
| R-S4 | 生活事件如何变成标签 | 自动对齐：流年干支（立春起年）、与原局四支的冲/合/刑/害、是否冲夫妻宫、所在大运、流年干对日主的十神 |
| R-S5 | 模板文件的身份 | `data/samples/_template.json` 是**可复制的合法样板**（本身能被采集），不是纯文档 |
| **R-S6** | 事件类别 | **受控枚举 12 项**；复合写法定向拆为 主类别 + `tags`；完全不可识别 → 报错并列出合法值。`tags` 保留未收录值，不丢信息 |
| **R-S7** | 规则打通 | 样本规则证据走**既有 `rules` 证据链**（`from=规则:<id>`、`to=<目标类别>`、`chartId=<样本ID>`），不另建库 → 自动继承「≥3 盘且 0 反例 → verified」门槛。B 族**不在单样本下结论**（`pending-ensemble`） |

## 6 已知未决

1. ~~事件类别无受控词表~~ **已解决（R-S6）**：12 项枚举 + 复合归一。
2. **样本量**：目前 1 条；A 族规则要 `verified` 需 ≥3 个不同样本，B 族要两组都非空——现在必然全是 `pending` / `样本不足`。

6. **`category` 目前是单值**：一次事件若跨两类（如"离婚+财产分割"）只能选主类，另一类进 `tags` 但不参与规则统计。
