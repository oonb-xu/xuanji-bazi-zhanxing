## 1 重构：把 (日干支, 月将, 占时) 直算课式的入口暴露出来

**动机（R-L1）**：古籍年份多不可考（邵彦和为北宋人，"戊申年"有多个候选），
而三传**完全由「日干支 + 月将 + 占时」三项决定** → 对拍不必知道年份。

现有引擎的入口是「真实时间 → 中气 → 月将」，把这三项裹住了。重构方式：

```js
export function compileFromGanZhi({ dayGz, yueJiang, zhanShi, dayNight = '昼' }) {
  const { riGan, riZhi } = splitGanZhi(dayGz);
  const tianPan  = buildTianPan(yueJiang, zhanShi);       // 第 2 步
  const siKe     = buildSiKe(riGan, riZhi, tianPan);      // 第 3 步
  const sanChuan = deriveSanChuan({ riGan, riZhi, tianPan, yueJiang, shiChen: zhanShi });  // 第 4 步
  const guiRen   = guiRenOf(riGan, dayNight);
  const tianJiang = buildTianJiang(guiRen, tianPan);      // 第 5 步
  return { dayGz, riGan, riZhi, yueJiang, zhanShi, dayNight, tianPan, siKe, sanChuan, guiRen, tianJiang };
}
```

**纯组合，零算法改动** —— 四个积木（`buildTianPan` / `buildSiKe` / `deriveSanChuan` / `buildTianJiang`）
本来就在引擎里，只是此前没有"绕过时间链路"的入口。

（重构中的小坑：`splitGanZhi` 返回的是 `{riGan, riZhi}` 而**不是** `{gan, zhi}` —— 首版按后者解构，
报 `未定义的天干：undefined`。）

**这三条是"从古籍原文反推引擎缺陷"的范例**：不是猜规则，而是原文的三传本身把规则指出来了。

## 5 新增裁定

| 编号 | 裁定 |
|---|---|
| **R-L3** | 引擎必须提供「**由 (日干支, 月将, 占时) 直算课式**」的入口（`compileFromGanZhi`），与「真实时间 → 中气 → 月将」的链路**并存**；前者供古籍对拍，后者供实占 |
| **R-L4** | 对拍不一致的课例**必须先逐条查明**（古本误字 / 抽取边界 / 引擎特殊课体）**再归因**，不得直接算作引擎错误 |
| **R-L5** | 现代案例集若为**有版权的商业出版物**，不得下载或传播；只能由用户提供文本后本地入库 |
