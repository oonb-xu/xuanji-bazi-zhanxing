## 1 ★ R-T1：真太阳时**不能**喂给星盘（规格 Step 1.2 的方向是错的）

规格写的是"调用真太阳时校正 → 再把校正后的时间输入星盘引擎"。按此执行会**把经度修正算两遍**：

```
真太阳时 = UT + 经度/15 + 均时差        ← 这个量本身已经是当地钟面读数
星盘所需 = UT（民用时按历史时区换算） + 经度（只用于宫位/上升）
```

**数值证明**（案例001，出生地已脱敏，时刻已脱敏）：

| 口径 | 上升 | 中天 |
|---|---|---|
| 正确（civil → UT） | 85.34° | 338.45° |
| 误用真太阳时当当地时间 | 69.48° | 321.66° |
| **偏差** | **15.86°** | **16.79°** |

偏差超过半个星座，且**不报错**——宫位、四轴、生时校正结论会整体错掉。

**裁定**：真太阳时**只用于中国侧**（八字时柱、六壬占时）；星盘一律用 `civil → UT` + 地理经度。
`truesolar.mjs` 的返回里 `chartUtc` 字段就是给星盘的，`apparentSolarLocal` 是给中国侧的，两者分开输出。

### R-T2（**待你裁定**）：八字时柱该用民用时还是真太阳时？

案例001 实测：民用 17:30 为**酉**时，真太阳时 16:26 为**申**时 → **时柱由 辛酉 变成 庚申**。
成都偏标准时经线 15.94°（≈64 分钟），这个差异在西部城市普遍存在。

本引擎**当前不做任何改动**：`tyme4ts` 按民用时出四柱（既有基线全部基于此），
`cli-rectify.mjs` 只在 `warnings` 里明确标出"真太阳时导致时辰变化，时柱口径需确认"。
**要不要把八字时柱切到真太阳时，是流派选择，必须你决定；我不会静默改。**

## 2 生时校正算法（`src/rectify/rectify.mjs`）

三类信号加权求和，逐候选时刻打分：

| 信号 | 内容 | 权重 |
|---|---|---|
| **S1 外行星行运** | 木/土/天/冥 在事件年内的黄经（5 天步长）与本命**四轴/太阳/月亮**的 0°/90°/180° 接触（orb 3°） | 0.5 |
| **S2 太阳弧** | 本命点 + 年龄×0.985647° 后的位置与四轴/日月的硬相位接触（经典校正工具） | 0.3 |
| **S3 八字流年** | 该候选时刻的时柱 → 流年与原局的刑冲引动（冲夫妻宫 1.5、其他引动 1.0、仅相害 0.3） | 0.2 |

- 事件**类别参与计算**（不是只当标签）：`CATEGORY_FOCUS` 让「婚恋→下降/天顶、事业→天顶/太阳、健康→上升/月亮…」的参照点权重 ×1.5。
- **收敛判据**：得分 ≥95% 峰值的候选时段宽度 ≤10 分钟 → `confidence: ±5min`；否则明确报
  `±Nmin（未达 ±5min，需追加事件）`。**不强行给 ±5min。**
- **可复算**：同输入同输出（自检里验证两次运行结果一致）——这是不用"AI 辩论"的核心原因。

## 3 Step 5 分支（已落到代码并实测）

| 条件 | 行为 |
|---|---|
| 事件 < 3 | **拒绝校正**，只输出原始双盘 + 八字，并打印"需补充事件"（实测：2 条 → 拒绝） |
| 时间为空/未知分钟 | 用给定时刻为初值并放大窗口；`confidence` 降级 |
| 中国境内 | 走 `truesolar.mjs`（含历史夏令时 + 经度 + 均时差） |
| 校正未收敛 | 输出 `±Nmin（未达 ±5min）` 并要求追加事件 |
| 批量 ≥10 案例 | 见 §6 未决（kerykeion 批量脚本尚未接） |

## 5 新增裁定

| 编号 | 未定义处 | 裁定 |
|---|---|---|
| **R-T1** | 真太阳时用在哪儿 | **只用于中国侧（时柱/占时）**；星盘用 `civil → UT` + 经度。误用会让四轴偏 >15° |
| **R-T2** | 八字时柱口径 | **待用户裁定**（民用时 vs 真太阳时）；当前保持民用时，仅在 `warnings` 标注差异，不静默改 |
| R-T3 | 校正算法 | 用**确定性评分法**（三类信号加权），不用无法复算的"AI 多智能体辩论"；同输入必须同输出 |
| R-T4 | 收敛口径 | ≥95% 峰值平台宽度 ≤10min 才算 `±5min`；否则如实报 `±Nmin（未达）`，**禁止强行输出 ±5min** |
| R-T5 | 事件不足 | <3 条 `rectify()` 直接返回 `ok:false`，不给 `corrected_time`（规格 Step 5 强制） |
| R-T6 | 历法引擎 | 复用已验收的 `tyme4ts`；不引入无 cp312 wheel 的 `sxtwl` |
| R-T7 | 乱码闸 | `npm test` 首条即跑 `verify-encoding.mjs`：源文件出现 U+FFFD 或连续乱码特征字 → **整套测试失败** |
