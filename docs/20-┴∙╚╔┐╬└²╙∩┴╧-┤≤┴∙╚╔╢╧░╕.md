### 两次解析器修正（都是静默错误）

| bug | 症状 | 根因 |
|---|---|---|
| 表头正则 | **0 命中** | 把**月将**写成「干+支」，而原文是**单个地支**（"午将"不是"丙午将"） |
| 三传正则 | 抽出 `子巳` 之类的噪声 | 只匹配「六亲+干支」，会从**四课盘面**误抓 → 必须**锚定天将后缀**（`六亲 干支 天将`） |

修正后三传与原文**逐字吻合**：

```
丁丑日午将未时 → 官丙子 官乙亥 子甲戌      （原文：官 丙子 蛇 / 官 乙亥 贵 / 子 甲戌 后）
庚戌日亥将辰时 → 父庚戌 官乙巳 子壬子      （原文：父 庚戌 合 ⊙ / 官 乙巳 常 / 子 壬子 蛇）
```

## 4 为什么这批语料重要 —— 它解开了 R-W14 的死结

`docs/18 §4.3` 的结论是：**六壬×占星融合的"符号层"因"零课例"而无法验证**。
现在有了 41 例**带真实应验**的古典课例 → **符号层第一次具备可验证条件**。

而且对拍**不需要年份**：原文已给出 **日干支 + 月将 + 占时** 三项，
三传完全由这三项决定 → **可逐例机检**（比八字对拍更干净：不需要出生时刻）。

## 5 下一步（唯一的工程量）

现有 `src/daliuren.mjs` 的入口是「真实时间 → 中气 → 月将」，
而古籍课例**年份不可考**（邵彦和为北宋人，戊申年有多个候选）。
→ 必须把第四步（发三传）与第五步（布天将）暴露为**由 (日干支, 月将, 占时) 直接调用**的入口。

**这是纯重构，不涉及算法改动**（天地盘 = 月将加占时；四课由日干与天地盘取；三传由四课按既有规则发）。
做完即可得到 **41 例的三传对拍率** —— 这将是六壬引擎第一次在**古典实测课例**上被检验。
