实施：2026-10-08。文件：`cli-occ.mjs`、`src/bazi/five-pillar.mjs`、`reports/korean-occ.md`。

| 项 | 设定 |
|---|---|

| 特征 | 三柱 12 特征（年月日 干/支/五行/日主/阴阳）+ **胎元 4 特征（干支/干/支/五行）** |

## 2 基线

| 基线 | 准确率 |
|---|---|
| 多数类（演艺，占训练集 36.3%） | **36.39%** |
| 均匀随机（8 类） | 12.50% |

## 3 主实验：加不加胎元

| 特征集 | 测试准确率 | 相对多数类 |
|---|---|---|
| 三柱（12 特征） | **38.64%** | +2.25pt |
| **三柱 + 胎元（第五柱，+4 特征）** | **36.28%** | **−0.10pt** |
| **胎元带来的增量** | **−2.36pt** | |

**→ 把胎元当第五柱，正确率没有提高，反而下降 2.36pt，并跌破多数类基线。**

## 4 ★ 为什么下降 —— 一个可以证明的结论

**胎元是月柱的双射**：`胎元 = (月干+1, 月支+3)`，60 种月柱 ↔ 60 种胎元，一一对应。

⇒ 对**任何**目标 Y 都有 **`MI(胎元 ; Y) ≡ MI(月柱 ; Y)`**。**胎元不可能提供月柱以外的新信息。**

**实测验证**（37,081 样本）：

```
月柱取值数 60｜胎元取值数 60｜双射？ true
MI(月柱;职业) = 0.01542617
MI(胎元;职业) = 0.01542617
差值 = 0.000e+0          ← 完全相等（不是"接近"，是 0）
```

**所以降分的机制很清楚**：朴素贝叶斯把**同一份信息**通过"月柱干支"与"胎元干支"两组特征**重复计入**，
等价于给月柱加倍权重 → 证据被过计 → 反而偏差更大。

> 顺带解释了单特征互信息表里的"假象"：表中 `taiYuan`（0.01543）看似高于 `m_branch`（0.00836），
> 但那只因为 `taiYuan` 同时编码了干与支；与 `MI(月柱组合)` 相比**分毫不差**。

## 5 结论

| 命题 | 结论 |
|---|---|
| 「胎元当第五柱能提高正确率」 | ❌ **不成立**（−2.36pt） |
| 「胎元完全没用」 | ❌ **也不对** —— 它携带的信息量**精确等于月柱**（0.01543 bits） |
| 正确的表述 | **胎元是月柱的确定性变换，可作月柱的"另一种写法"（换象），但不是独立的一柱** |

**要让它成为真正独立的第五柱，信息来源必须在月柱之外**（出生时刻、地点、或其他独立观测）——
而胎元的定义决定了它做不到。**这是定义层面的限制，不是参数没调好。**

## 6 新增裁定

| 编号 | 裁定 |
|---|---|
| **R-B12** | **胎元不是独立柱**：`MI(胎元;Y) ≡ MI(月柱;Y)`（双射，可证）。作为**换象/辅助记法**可用；作为**独立特征**加入模型不得期待增益，实测为 −2.36pt |
| **R-X2** | **CLI 文件不得被 import**：`cli-korean.mjs` 有顶层副作用（载 CSV、打印、跑命令），`import { taiYuanOf }` 会把整个 CLI 重跑一遍 → 可复用逻辑必须放**纯模块**（已抽到 `src/bazi/five-pillar.mjs`） |
| **R-X3** | 任何"加一个特征看是否提升"的实验，**必须同时给出基线（多数类/随机）与单特征互信息** —— 只看准确率变化会把"重复计数"误读成"特征有用/没用" |

## 7 已知未决

1. **职业目标本身含噪**：多职业取第一个、未控国别/年代/性别 → 绝对准确率不可当能力指标（38.6% 只比多数类高 2.25pt）。
2. **未做的对照**：应再测"**只给月柱**（不给年/日）"与"只给胎元"两组的准确率 —— 按 R-B12，二者应当**几乎相同**；跑这一组可把结论钉死。本轮因预算未跑。
3. **第 1 项待办（补六壬课例）仍未完成**：见 `docs/18 §4.3`，必须有人提供 ≥30 条**带真实结果的六壬课例**才能验证符号层。本项目**一条都没有**，我不会编造。
