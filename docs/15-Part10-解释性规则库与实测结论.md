## 0 ★ 先回答 70% 这个验收线（有权威数据，不是我的判断）

BaziQA-Benchmark 原论文（[arXiv:2602.12889](https://arxiv.org/abs/2602.12889)，TABLE I，宏平均、多轮设置）：

| 模型 | 宏平均准确率 | 95% CI |
|---|---|---|
| DeepSeek-Chat-V3 | **36.7%** | [33.2, 40.2] |
| DeepSeek-R1 | 34.1% | [29.6, 38.6] |
| **GPT-5.1-Chat** | **32.5%** | [29.0, 36.0] |
| **Gemini-3-Pro** | **32.1%** | [26.6, 37.6] |
| Gemini-2.5-Flash | 32.4% | [29.7, 35.1] |

论文原文：**"even the strongest models answering fewer than half of the questions correctly"**
（最强的模型都答不对一半），"remain far from saturation"。

**结论：70% 约为当前 SOTA 的 1.9 倍**，且该基准上**没有任何模型**（含 GPT-5.1、Gemini-3-Pro）超过 37%。
**我不会伪造 70%。** 下面给出我实际做到的、以及为什么天花板在这里。

**另外两件必须澄清的**：

1. **`bazi-calculate-rlvr` 不存在**（GitHub 搜索零结果）→ 那个"20w 数据"没有可用的具名来源。
   可用的替代已在手：VedAstro **15,807 盘**训练库（58.7 MB，含真实婚姻标签）+ celebrity50 的**带日期真实事件**。
2. **该基准把排好的命盘文本直接给模型**（论文 §II-C：目的是 "isolate symbolic inference from calendrical
   conversion"）→ 所以**扩充规则库不可能改变成绩**。缺的不是规则而是**该人物的具体人生事实**，
   而它在盘里不以可解码形式存在。这一步认知比再多写 100 条规则都重要。

## 1 三大领域规则库（已实现，规则编号可人工裁定）

### 领域一：六亲（K 族）
定位等式（10.2.1）与宫位（10.2.3）已编码：`KIN_STAR`（男：正财=妻/偏财=父/正印=母/官杀=子/比劫=兄；
女：正官=夫/七杀=情人/食伤=子/印=母/财=父/比劫=姐妹）、`KIN_PALACE`（年=祖辈父、月=父母兄弟、日支=配偶、时=子女）。

| 规则 | 触发条件 | 结论 |
|---|---|---|
| K-001 | 六亲星被重克（出现 ≥2 次） | 该六亲有灾 / 缘分薄 |
| K-002 | 六亲星被冲 **且** 其宫位被冲 | 该六亲早逝或重大变故 |
| K-003 | 六亲星为忌神 | 该六亲带来拖累 |
| K-004 | 六亲星为用神而弱 | 该六亲有心无力 |
| K-005 | 六亲星缺（计数 0） | 该六亲缘薄 / 缺位 |

### 领域二：疾病（H 族）
五行-脏腑映射表（10.2.1）已编码为 `ORGAN_TABLE`（含过旺/过弱表现与**选项匹配关键词**）。

| 规则 | 触发条件 | 结论 |
|---|---|---|
| H-001 | 某五行过旺且无制 | 该脏腑**亢进**类疾病 |
| H-002 | 某五行过弱且被克 | 该脏腑**衰退**类疾病 |
| H-003 | 该五行被重克 | 急性病 / 外伤风险 |
| H-004 | 日支（身体宫）被冲 | 整体健康根基不稳 |
| H-005 | 时柱（晚年宫）被冲 | 晚年健康隐患 |

### 领域三：时间应期（T 族）
`yearInteraction()` 实现流年干支与原局的逐柱互动：冲 / 合 / 伏吟 / 天克地冲 / 三刑（简化表）。

| 规则 | 触发条件 | 结论 |
|---|---|---|
| T-001 | 大运流年成三合/三会 | 重大事件（婚/迁/变） |
| T-002 | 冲日支 | 婚姻动荡 / 身体变动 |
| T-003 | 冲时柱 | 子女 / 事业 / 晚年有变 |
| T-004 | 冲年柱 | 长辈 / 祖业 / 根基有变 |
| T-005 | 引动三刑 | 官非 / 手术 / 意外 |
| T-006 | 天克地冲（返吟） | 剧烈变动 |
| T-007 | 伏吟（流年与某柱同） | 事件重复或强化 |

### 选项感知作答器（本轮真正的工程改进）

前一版靠**手写关键词表**匹配选项文本 → 几乎不触发（200 题里 196 题"无规则命中"）。
本版先把每个选项**解析成结构特征**：`parseOption()` 抽取**年份 / 干支 / 脏腑词 / 亲属词 / 强弱词**，
再用 K/H/T 规则逐项打分（年份类选项会真的去算该年的冲合刑害），取 argmax。

| 指标 | 旧版（关键词表） | **Part 10 选项感知** |

## 3 本轮修掉的又一个真 bug（报告统计量）

`vsChance()` 的返回写成 `{ rate: p, z, p }` —— **简写属性把 `p` 又指回准确率**，
于是所有报告里的"p 值"其实恒等于准确率（`aboveChance` 用的是正确的 `pv`，所以只有 `p` 字段错）。
已修为 `p: pv` 并在自检里钉住（`p` 不得等于 `rate`；25% 时单侧 p 必须 =0.5）。
→ 因此 `docs/14` 里旧基线的"p=0.22"应读作**准确率 22%**，正确单侧 p 为 **0.163**。已在此更正。

## 4 ★ 用大师的人工修正结论**反向优化 rule 库**（本轮核心）

用户指示：把专家答案当**修正信号**去反优化规则库，不设 70% 硬指标。实现方式：

1. **把每条规则变成一个特征**（`optionFeatures()`：该规则是否被该选项触发，0/1 指示值），
   权重 = 该规则值多少分 → **拟合权重就是"反向修正 rule 库"**，且每个数字都可人工裁定。
2. `fitWeights()` 用**训练集（2021–2023，120 题）的专家答案**做**坐标上升**（网格 [-3,-2,-1,0,.5,1,1.5,2,3,4]，3 轮），
   目标是训练集准确率；**测试集（2024–2025，80 题）只看不调**。
3. 确定性算法（无随机），自检里验证**可复算**。

| 集合 | 手写权重（Part 10 初始） | **拟合后** | 变化 |
|---|---|---|---|
| 训练集（120，参与拟合） | 29.2% | **39.2%** | **+10.0pt** |
| **测试集（80，未参与拟合）** | 21.3% | **22.5%** | **+1.3pt** |
| 全量 200（**不构成公平成绩**） | 52 (26.0%) | 65 (32.5%) | +6.5pt |

拟合轨迹：29.2% → 34.2% → 37.5% → **39.2%**（3 轮内收敛）。

### 🔴 最重要的发现：几条时间规则被判定为**方向写反了**

| 特征（规则） | 初始权重 | **拟合权重** | 含义 |
|---|---|---|---|
| `T-002_chongDay`（流年冲日支 → 婚姻动荡） | +2.0 | **−2.0** | **反向** |
| `T-003_chongHour`（流年冲时柱 → 子女/事业有变） | +1.5 | **−3.0** | **反向** |
| `T-006_tianKeDiChong`（天克地冲 → 剧烈变动） | +2.5 | **−3.0** | **反向** |
| `T-004_chongYear`（冲年柱 → 长辈有变） | +1.5 | +1.5 | 保持 |

**含义**：在"四选一挑年份"这个任务里，**流年冲日支/时柱的那一年，反而更不可能是专家标答**。
我的解读（三种可能，按可能性排序）：
1. **出题设计**会把命局最"显眼"的冲合放在**干扰项**里 —— 直觉上最像的年份不是答案；
2. **我的流年模型过于简化**（未含大运、三刑表不全、无合化），
   所以在候选年份之间做**区分**时，我算出的冲合方向与真信号相反；
3. 题目问的事件类型与"冲日支"对应的领域本来就不一致。

**这不等于"冲日支不主婚姻动荡"**（那是断语层面的问题），
而是说：**拿它当"选年份"的判据时，方向是反的**。这两件事必须分开讲。

### ⚠️ 但必须同时说清：这个反向优化的**泛化很差**

训练 **+10.0pt** vs 测试 **+1.3pt** → **过拟合量约 8.7pt**。
测试集 22.5% **仍低于 25% 随机线**。全量 200 题的 32.5% **是脏数字**（拟合时看过其中 120 题），
不能拿去和 SOTA（32–37%）比。

**诚实结论**：**专家答案在这批题目上不是一个跨年份稳定的可学目标** ——
这恰好独立印证了原论文的发现（"year-wise accuracy varies non-monotonically"）。
用同一年的答案去拟合、再在同一年评估，能得到一个漂亮的数字，但那是**自欺**。

### 【待验证规则】（50–70%）

- **H-002（58%）、T-002（63%）**：接近 70% 线，但支持案例数只有 17 / 8 条，置信区间很宽
  → 建议扩充案例后再评估，不要现在就当结论。
- **六亲宫位共振**（年柱透偏财 且 父星被冲）：在 24 道六亲题上命中 6 题（25%），无增益 → 待验证。

### 【冲突规则】

| 冲突 | 双方 | 裁决 |
|---|---|---|
| 同一命例上 K-005（星缺→缘薄）与 T-004（冲年柱→长辈有变）给相反方向 | K-005 vs T-004 | 按 10.4 步骤 3 的**特异性优先**：T-004 指定了具体柱与具体年份，比"星缺"更具体 → 采信 T-004 |
| H-001（过旺→亢进）与 H-002（过弱→衰退）在同一脏腑同时触发 | H-001 vs H-002 | 五行不可能同时过旺与过弱，二者同时触发说明**该五行分布处于 2 分（中位）** → 判定为"无信号"，不作答（避免了 3 例误答） |

### 【数据库更新建议】

- **建议新增字段**：`questions[].domain`（现无 gold domain 标注，论文自己也说用的是启发式标注，
  导致我的分题类统计有误分类风险）；`person.chart_text`（论文用固定命盘文本，我目前是自己现算，两者口径需对齐）。
- **建议补充案例**：BaziQA 仅 200 题，要检出 35% vs 25% 需要 ~300 题、检出 30% vs 25% 需 ~1,100 题
  → **优先补的是题量**，而不是规则数。
- **建议废弃规则**：本轮 T-007（伏吟，33%）、K-004（用神弱，无命中案例）—— 先撤出候选池。
- **强烈建议换评估目标**：改用 celebrity50 的**带日期真实事件**做"**应期对拍**"
  （预测年份 vs 真实年份），这是唯一能把"命理是否有效"变成可量化问题的路径；
  本题库的多选题本质是"猜该人物的私事"，规则引擎在原理上就无法胜任。

## 8 已知未决（诚实清单）

1. **70% 不可达**，证据见 §0；这不是规则库做得不够好，而是任务形态与信息论限制。
2. **若一定要 70%**，只有三条路，且都不属于"做规则库"：
   ① 换任务（改成**信息完整**的任务，例如给定全部事件后判断命局特征）；
   ② **降低难度**（改成二选一 → 随机线 50%，70% 才有意义）；
   ③ **引入题目之外的信息**（人物身份/答案分布泄漏）—— 这是作弊，我不会做。
3. **本引擎在 BaziQA 上低于大模型**（29.0% vs 32–37%），如实记录。
4. 三刑表是简化实现（未含完整自刑/无恩之刑全集）；大运未参与作答（只用了流年）。
5. 数据缺出生地点 → 真太阳时不可用（R-Q5）。
